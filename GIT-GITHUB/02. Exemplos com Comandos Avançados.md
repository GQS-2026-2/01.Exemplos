# ⚔️ Git Avançado — Conflitos, Merge, Rebase e Recuperação

Este guia cria conflitos reais e mostra como resolvê-los utilizando `merge`, `rebase`, `cherry-pick`, `revert` e `reset`.

> ✅ **Pré-requisitos**
>
> - Git instalado e configurado;
> - conhecimento dos comandos básicos;
> - familiaridade com `add`, `commit`, `branch`, `switch`, `log` e `status`.

---

# 🧪 0) Preparação do cenário

Crie um repositório de testes:

```bash
mkdir git-conflitos
cd git-conflitos
git init -b main
```

Crie o arquivo:

```bash
echo "linha 1" > notas.txt
echo "linha 2" >> notas.txt
echo "linha 3" >> notas.txt
```

Depois:

```bash
git add notas.txt
git commit -m "chore: cria notas.txt com três linhas"
```

Visualize:

```bash
cat notas.txt
```

---

# 🧩 A) Conflito com merge

## 1️⃣ Criar a primeira branch

```bash
git switch -c feature/a
```

Abra `notas.txt` no editor e altere:

```text
linha 2
```

para:

```text
linha 2 - alterada na feature A
```

Depois:

```bash
git add notas.txt
git commit -m "feat: altera linha 2 na feature A"
```

> 💡 A edição manual foi escolhida para que o exercício funcione da mesma forma em Windows, macOS, Linux e GitHub Codespaces.

---

## 2️⃣ Criar uma alteração conflitante na `main`

```bash
git switch main
```

Abra `notas.txt` e altere a mesma linha para:

```text
linha 2 - alterada na main
```

Depois:

```bash
git add notas.txt
git commit -m "feat: altera linha 2 na main"
```

Agora existem duas versões diferentes da mesma linha.

---

## 3️⃣ Tentar fazer o merge

```bash
git merge feature/a
```

Uma saída semelhante a esta pode aparecer:

```text
Auto-merging notas.txt
CONFLICT (content): Merge conflict in notas.txt
Automatic merge failed; fix conflicts and then commit the result.
```

---

## 4️⃣ Inspecionar o conflito

```bash
git status
git diff
```

O arquivo terá marcadores semelhantes a:

```text
linha 1
<<<<<<< HEAD
linha 2 - alterada na main
=======
linha 2 - alterada na feature A
>>>>>>> feature/a
linha 3
```

### O que significam?

```text
<<<<<<< HEAD
```

Versão da branch atual.

```text
=======
```

Separador.

```text
>>>>>>> feature/a
```

Versão que está sendo integrada.

---

## 5️⃣ Resolver manualmente

Edite o arquivo removendo os marcadores.

Exemplo:

```text
linha 1
linha 2 - resolução combinada
linha 3
```

Depois:

```bash
git add notas.txt
git commit -m "merge: resolve conflito em notas.txt"
```

Verifique:

```bash
git log --oneline --graph --decorate --all
```

---

## 🛑 Abortar um merge

Se não quiser continuar:

```bash
git merge --abort
```

---

# 🔁 B) Conflito com rebase

O `rebase` reaplica commits sobre uma nova base.

## 1️⃣ Criar uma branch

Partindo da `main`:

```bash
git switch -c feature/b
```

Adicione ao final de `notas.txt`:

```text
linha 4 - feature B
```

Depois:

```bash
git add notas.txt
git commit -m "feat: adiciona linha 4 na feature B"
```

---

## 2️⃣ Criar outra versão na `main`

```bash
git switch main
```

Adicione ao final:

```text
linha 4 - main
```

Depois:

```bash
git add notas.txt
git commit -m "feat: adiciona linha 4 na main"
```

---

## 3️⃣ Rebase da feature sobre a `main`

```bash
git switch feature/b
git rebase main
```

Se houver conflito:

```bash
git status
```

Edite `notas.txt` e escolha a versão final.

Por exemplo:

```text
linha 1
linha 2 - resolução combinada
linha 3
linha 4 - resolução do rebase
```

Depois:

```bash
git add notas.txt
git rebase --continue
```

Se houver novos conflitos, repita:

```text
editar → git add → git rebase --continue
```

---

## ⏭️ Pular um commit durante o rebase

```bash
git rebase --skip
```

> ⚠️ Use somente quando tiver certeza de que o commit pode ser descartado.

---

## 🛑 Abortar o rebase

```bash
git rebase --abort
```

Isso retorna ao estado anterior ao início do rebase.

---

## 4️⃣ Integrar a feature após o rebase

```bash
git switch main
git merge feature/b
```

Se a `main` não tiver avançado, o merge pode ocorrer por **fast-forward**.

---

# 🌿 C) Rebase interativo

O rebase interativo permite:

- reorganizar commits;
- juntar commits;
- alterar mensagens;
- remover commits.

Crie uma branch:

```bash
git switch -c feature/historico
```

Faça três commits:

```bash
echo "a" >> dev.txt
git add dev.txt
git commit -m "WIP"

echo "b" >> dev.txt
git add dev.txt
git commit -m "fix"

echo "c" >> dev.txt
git add dev.txt
git commit -m "mais coisas"
```

Veja:

```bash
git log --oneline
```

Inicie:

```bash
git rebase -i HEAD~3
```

O editor mostrará algo semelhante a:

```text
pick <hash1> WIP
pick <hash2> fix
pick <hash3> mais coisas
```

Pode ser alterado, por exemplo, para:

```text
pick <hash1> WIP
squash <hash2> fix
reword <hash3> mais coisas
```

### Comandos comuns

- `pick` → mantém o commit;
- `reword` → mantém o commit, mas altera a mensagem;
- `edit` → pausa para alterar o commit;
- `squash` → junta ao commit anterior e permite combinar mensagens;
- `fixup` → junta ao anterior descartando a mensagem atual;
- `drop` → remove o commit.

> ⚠️ Evite reescrever o histórico de branches compartilhadas sem alinhamento com a equipe.

# 🎯 D) Cherry-pick

O `cherry-pick` permite aplicar um commit específico em outra branch.

Crie:

```bash
git switch main
git switch -c feature/config
```

Crie o arquivo:

```bash
echo "config=ABC" > app.conf
git add app.conf
git commit -m "feat: adiciona configuração ABC"
```

Copie o hash:

```bash
git log --oneline
```

Volte para `main`:

```bash
git switch main
```

Crie uma versão diferente:

```bash
echo "config=XYZ" > app.conf
git add app.conf
git commit -m "chore: define configuração XYZ"
```

Agora aplique o commit da feature:

```bash
git cherry-pick <HASH_DO_COMMIT>
```

Se houver conflito:

```bash
git status
```

Resolva o arquivo e depois:

```bash
git add app.conf
git cherry-pick --continue
```

Para abortar:

```bash
git cherry-pick --abort
```

# 🧹 E) Revert x Reset

## `git revert`

Cria **um novo commit** que desfaz outro commit.

```bash
git revert <HASH>
```

É geralmente apropriado para histórico que já foi publicado/compartilhado.

---

## `git reset`

Move o ponteiro da branch.

### Soft

```bash
git reset --soft HEAD~1
```

O commit é removido do histórico atual, mas as alterações continuam em **staging**.

### Mixed

```bash
git reset HEAD~1
```

As alterações continuam na working tree, mas saem do staging.

### Hard

```bash
git reset --hard HEAD~1
```

> ⚠️ Descarta commits e alterações locais de acordo com o ponto escolhido. Use com muito cuidado.

---

# 📦 F) Stash

O `stash` guarda alterações temporariamente.

Faça uma alteração em algum arquivo e execute:

```bash
git stash
```

Veja os stashes:

```bash
git stash list
```

Recupere:

```bash
git stash pop
```

Incluindo arquivos ainda não rastreados:

```bash
git stash -u
```

# 🧭 G) Sincronizar uma feature com a `main` remota

Em um projeto colaborativo:

```bash
git fetch origin
git rebase origin/main
```

Isso significa:

> reaplicar os commits da branch atual sobre a versão mais recente de `origin/main`.

Se houver conflito:

```bash
git status
```

Resolva e continue:

```bash
git add <arquivo>
git rebase --continue
```

Se a branch ainda nunca foi enviada:

```bash
git push -u origin nome-da-branch
```

Se ela já havia sido enviada antes do rebase, os hashes dos commits terão mudado. Nesse caso:

```bash
git push --force-with-lease
```

> ⚠️ Prefira `--force-with-lease` a `--force`, pois ele adiciona uma proteção contra sobrescrever alterações remotas inesperadas.

# 🧠 Merge ou Rebase?

Não existe uma única estratégia correta para todos os projetos.

## Merge

```bash
git merge feature/x
```

Pode ser útil quando a equipe deseja preservar explicitamente a integração entre branches.

## Rebase

```bash
git rebase main
```

Pode ser útil para reorganizar uma feature sobre uma base mais recente e manter o histórico linear.

> ✅ A estratégia deve seguir o fluxo e as regras adotadas pela equipe.

# 🧭 Dicas práticas

Antes de operações importantes:

```bash
git status
```

Atualize as referências remotas:

```bash
git fetch origin
```

Visualize o histórico:

```bash
git log --oneline --graph --decorate --all
```

Veja alterações:

```bash
git diff
```

Veja alterações no staging:

```bash
git diff --staged
```

Remova um arquivo do staging:

```bash
git restore --staged <arquivo>
```

Descarte alterações locais:

```bash
git restore <arquivo>
```

> ⚠️ O último comando perde alterações não commitadas do arquivo.

# 💻 GitHub Codespaces

Todos os exercícios podem ser realizados no GitHub Codespaces.

## Como abrir

1. Acesse o repositório no GitHub;
2. clique em **Code**;
3. abra **Codespaces**;
4. clique em **Create codespace on main**.

## Vantagens

- Git instalado;
- terminal integrado;
- editor visual;
- destaque para conflitos;
- possibilidade de praticar merge, rebase e cherry-pick.

> 💡 Para os exercícios de conflito, edite os arquivos pelo editor do Codespace. Assim o material funciona independentemente das diferenças entre comandos de macOS, Linux e Windows.
