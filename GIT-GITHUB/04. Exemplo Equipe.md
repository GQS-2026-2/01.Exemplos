# 👩‍💻👨‍💻 Git em Equipe com Java, GitHub e Codespaces

Mini-projeto para praticar Git e GitHub em uma equipe de 3 pessoas.

Cada integrante implementará uma operação da classe `Calc` em uma branch diferente, enviará sua branch ao GitHub, abrirá um Pull Request e participará da resolução de um conflito intencional no `README.md`.

---

# 🎯 Objetivos 

Ao final da atividade, a equipe deverá ser capaz de:

* trabalhar no mesmo repositório GitHub;
* utilizar o GitHub Codespaces como ambiente de desenvolvimento;
* identificar em qual branch está trabalhando;
* criar e trocar branches;
* trabalhar com uma branch de desenvolvimento chamada `dev`;
* criar branches do tipo `feature`;
* realizar commits;
* enviar alterações para o GitHub;
* abrir Pull Requests;
* realizar Code Review;
* integrar funcionalidades na `dev`;
* atualizar uma feature utilizando `rebase`;
* identificar conflitos;
* resolver conflitos;
* integrar a versão final da `dev` na `main`.

---

# 💻 Ambiente utilizado

Toda a atividade poderá ser realizada pelo navegador utilizando:

> **GitHub Codespaces**

Não será necessário:

* instalar Git localmente;
* instalar Java localmente;
* instalar Maven localmente;
* utilizar Git Bash;
* utilizar CMD;
* clonar o projeto para o computador.

Cada integrante deverá utilizar **sua própria conta do GitHub**.

---

# 👥 Organização da equipe

A equipe terá **3 integrantes**.

| Pessoa   | Branch                  | Responsabilidade          |
| -------- | ----------------------- | ------------------------- |
| Pessoa A | `feature/soma`          | Implementar soma          |
| Pessoa B | `feature/subtracao`     | Implementar subtração     |
| Pessoa C | `feature/multiplicacao` | Implementar multiplicação |

Além da implementação da operação, todos modificarão propositalmente **a mesma linha do `README.md`**.

Essa alteração será utilizada para provocar um conflito controlado.

---

# 🌳 Fluxo de branches utilizado

Neste exemplo serão utilizadas três categorias de branch:

```text
main
 │
 └── dev
      │
      ├── feature/soma
      ├── feature/subtracao
      └── feature/multiplicacao
```

## `main`

Representa a versão **final e estável** do projeto.

A equipe **não desenvolverá diretamente na `main`**.

---

## `dev`

Será utilizada para integrar as funcionalidades desenvolvidas pela equipe.

Todas as features deverão ser integradas primeiro na:

```text
dev
```

---

## `feature/...`

Cada integrante desenvolverá sua tarefa em uma branch própria.

Exemplo:

```text
feature/soma
feature/subtracao
feature/multiplicacao
```

---

# 🚨 Regras importantes

Durante esta atividade:

> ❌ Não programar diretamente na `main`.

> ❌ Não programar diretamente na `dev`.

> ✅ Todo desenvolvimento deverá acontecer em uma branch `feature`.

O fluxo será:

```text
feature
   ↓
Pull Request
   ↓
dev
   ↓
Pull Request final
   ↓
main
```

# ⚠️ Rebase depois de um `push`

O ideal neste exercício é realizar o `rebase` **antes do primeiro `push`**.

Porém, se uma branch já tiver sido enviada ao GitHub e depois passar por `rebase`, os hashes dos commits serão alterados.

Nesse caso, poderá ser necessário:

```bash
git push --force-with-lease
```

> ⚠️ Não utilize `git push --force` indiscriminadamente.

O `--force-with-lease` adiciona uma verificação antes de sobrescrever a branch remota.

# 🧠 Fluxo para memorizar

Antes de iniciar uma nova tarefa:

```bash
git switch dev
git pull origin dev
```

Criar a feature:

```bash
git switch -c feature/tarefa
```

Desenvolver e testar.

Depois:

```bash
git status
git add .
git commit -m "feat: implementa tarefa"
```

Atualizar a feature:

```bash
git fetch origin
git rebase origin/dev
```

Se houver conflito:

```text
resolver arquivos
↓
git add arquivo
↓
git rebase --continue
```

Depois:

```bash
git push -u origin feature/tarefa
```

No GitHub:

```text
feature/tarefa
      ↓
Pull Request
      ↓
dev
```
