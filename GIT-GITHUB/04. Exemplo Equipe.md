# 👩‍💻👨‍💻 Git em Equipe com Java

Mini-projeto para praticar Git e GitHub em uma equipe de 3 pessoas.

Cada integrante implementará uma operação da classe `Calc` em uma branch diferente, enviará sua branch ao GitHub, abrirá um Pull Request e participará da resolução de um conflito intencional no `README.md`.

---

# 🎯 Objetivos de aprendizagem

Ao final, a equipe deverá ser capaz de:

- clonar um repositório;
- criar e trocar branches;
- realizar commits;
- enviar branches para o GitHub;
- abrir Pull Requests;
- revisar código;
- integrar alterações;
- atualizar uma feature com a `main`;
- identificar e resolver conflitos;
- utilizar rebase de forma controlada.

---

# ✅ Pré-requisitos

- Git instalado;
- Java 21 recomendado;
- Maven;
- GitHub;
- repositório com acesso para os três integrantes.

> 💻 O exercício também pode ser realizado pelo **GitHub Codespaces**.

---

# 👥 Organização da equipe

| Pessoa | Branch | Responsabilidade |
|---|---|---|
| Pessoa A | `feature/soma` | implementar soma |
| Pessoa B | `feature/subtracao` | implementar subtração |
| Pessoa C | `feature/multiplicacao` | implementar multiplicação |

Todos também alterarão propositalmente a **mesma linha do `README.md`** para gerar conflitos.

## `src/main/java/equipe/Calc.java`

```java
package equipe;

public class Calc {

    // Pessoa A
    public int soma(int a, int b) {
        return 0;
    }

    // Pessoa B
    public int subtracao(int a, int b) {
        return 0;
    }

    // Pessoa C
    public int multiplicacao(int a, int b) {
        return 0;
    }
}
```

---

## `src/main/java/equipe/Main.java`

```java
package equipe;

public class Main {

    public static void main(String[] args) {

        Calc c = new Calc();

        System.out.println("2 + 3 = " + c.soma(2, 3));
        System.out.println("3 - 2 = " + c.subtracao(3, 2));
        System.out.println("2 * 3 = " + c.multiplicacao(2, 3));
    }
}
```

No início, o resultado será:

```text
2 + 3 = 0
3 - 2 = 0
2 * 3 = 0
```

Ao final:

```text
2 + 3 = 5
3 - 2 = 1
2 * 3 = 6
```

Antes de iniciar, certifique-se de que está na `main`:

```bash

```

## 1️⃣ Criar branch

```bash
git switch -c feature/subtracao
```

## 2️⃣ Implementar

```java
public int subtracao(int a, int b) {
    return a - b;
}
```

## 3️⃣ Alterar a mesma linha do README

Exemplo:

```text
Linha da equipe (edite ESTA MESMA LINHA para criar conflito): Equipe = [Pessoa B]
```

## 4️⃣ Testar

```bash
mvn -q -DskipTests package
java -cp target/git-equipe-java-1.0.0.jar equipe.Main
```

## 5️⃣ Criar o commit ANTES de fazer rebase

```bash
git add .
git commit -m "feat: implementa subtracao e atualiza equipe"
```

## 6️⃣ Atualizar a feature com a `main` remota

Se o PR da Pessoa A já foi integrado:

```bash

git rebase origin/main
```

Provavelmente ocorrerá conflito no `README.md`.

---

# ⚔️ Resolver o conflito durante o rebase

O arquivo poderá aparecer assim:

```text
<<<<<<< HEAD
Linha da equipe (edite ESTA MESMA LINHA para criar conflito): Equipe = [Pessoa A]
=======
Linha da equipe (edite ESTA MESMA LINHA para criar conflito): Equipe = [Pessoa B]
>>>>>>> <commit>
```

Edite para:

```text
Linha da equipe (edite ESTA MESMA LINHA para criar conflito): Equipe = [Pessoa A, Pessoa B]
```

Depois:

```bash
git add README.md
git rebase --continue
```

Se o editor de mensagem abrir, salve e feche.

Confira:

```bash
git status
```

Depois:

```bash
git push -u origin feature/subtracao
```

Abra o PR e faça o merge após review.

# ⚠️ Rebase depois de um push

Se uma branch já tiver sido enviada ao GitHub e depois passar por `rebase`, seus commits terão novos hashes.

Nesse cenário, pode ser necessário:

```bash
git push --force-with-lease
```

> ⚠️ Não use `--force` sem necessidade.  
> `--force-with-lease` adiciona proteção contra sobrescrever alterações remotas inesperadas.

# ☕ Java 21 no Codespaces

Primeiro verifique:

```bash
java -version
mvn -v
```

Se o ambiente já tiver Java 21 configurado, **não é necessário instalar novamente**.

Caso seja necessário em uma imagem Ubuntu/Debian compatível:

```bash
sudo apt-get update
sudo apt-get install -y openjdk-21-jdk
```

Veja as versões disponíveis:

```bash
sudo update-alternatives --list java
sudo update-alternatives --list javac
```

Se houver mais de uma:

```bash
sudo update-alternatives --config java
sudo update-alternatives --config javac
```

Confirme:

```bash
java -version
javac -version
mvn -v
```

> 💡 Evite alterar `JAVA_HOME` manualmente se o Java 21 já estiver corretamente configurado no ambiente.

# 🎓 Desafio final

Depois da conclusão do exercício, cada integrante deverá explicar:

1. o que é uma branch;
2. por que o trabalho foi feito fora da `main`;
3. o que é um Pull Request;
4. por que ocorreu o conflito;
5. como o Git identifica um conflito;
6. o que `git rebase origin/main` fez;
7. qual a diferença entre `merge` e `rebase`;
8. por que `--force-with-lease` é preferível a `--force` após um rebase publicado.
