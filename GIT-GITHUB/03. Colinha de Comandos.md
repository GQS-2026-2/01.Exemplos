# 📘 Git — Colinha de Comandos e Flags

Este documento reúne comandos, flags e exemplos úteis do Git em um único lugar.

---

# 📦 Repositório e configuração

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git init` | `-b <nome>` | Inicia um repositório e pode definir a branch inicial | `git init -b main` |
| `git clone <url>` | `-b`, `--depth`, `--single-branch` | Clona um repositório | `git clone -b main <url>` |
| `git config` | `--global`, `-l`, `--list` | Configura usuário e opções | `git config --global user.name "Seu Nome"` |
| `git remote` | `-v` | Lista remotos | `git remote -v` |
| `git remote add` | — | Adiciona um remoto | `git remote add origin <url>` |
| `git remote set-url` | — | Altera a URL de um remoto | `git remote set-url origin <nova-url>` |

---

# ✍️ Staging e commits

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git status` | `-s`, `-b` | Mostra o estado do repositório | `git status -sb` |
| `git add` | `-A`, `-p`, `-N` | Adiciona alterações ao staging | `git add -A` |
| `git restore` | `--staged`, `-p` | Restaura arquivos ou remove do staging | `git restore --staged arquivo.java` |
| `git rm` | `-r`, `--cached`, `-f` | Remove arquivos do Git/working tree | `git rm --cached .env` |
| `git mv` | — | Move ou renomeia arquivo | `git mv Antigo.java Novo.java` |
| `git commit` | `-m`, `-a`, `--amend`, `-S` | Registra alterações | `git commit -m "feat: x"` |

> 💡 `git commit -a` inclui automaticamente alterações de arquivos **já rastreados**, mas não adiciona arquivos novos.

# 🌿 Branches

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git branch` | `-a`, `-r`, `-d`, `-D`, `-m` | Lista, remove ou renomeia branches | `git branch -a` |
| `git branch --show-current` | — | Mostra a branch atual | `git branch --show-current` |
| `git switch` | `-c`, `-` | Troca/cria branches | `git switch -c feature/api` |
| `git checkout` | `-b`, `-B` | Comando tradicional para troca/criação de branch e outras operações | `git checkout -b feature/api` |

> ✅ Para novos exemplos didáticos, prefira `git switch` para branches.  
> `git checkout` continua válido e é comum em projetos e materiais antigos.

# 🔀 Integração

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git merge` | `--no-ff`, `--squash`, `--abort` | Integra históricos | `git merge feature/api` |
| `git rebase` | `-i`, `--onto`, `--continue`, `--abort`, `--skip` | Reaplica commits sobre outra base | `git rebase main` |
| `git cherry-pick <hash>` | `-n`, `-x`, `--continue`, `--abort` | Aplica um commit específico | `git cherry-pick abc1234` |

# ⬆️⬇️ Sincronização

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git fetch` | `-p`, `--all`, `--tags` | Baixa referências remotas sem integrar automaticamente | `git fetch origin` |
| `git pull` | `--rebase`, `--ff-only` | Baixa e integra alterações | `git pull --rebase` |
| `git push` | `-u`, `--tags`, `--delete`, `--force-with-lease` | Envia commits/refs ao remoto | `git push -u origin feature/x` |

# 🔎 Inspeção e histórico

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git log` | `--oneline`, `--graph`, `--decorate`, `-p`, `-n` | Exibe histórico | `git log --oneline --graph --decorate --all` |
| `git diff` | `-w`, `-b`, `--staged`, `--name-only` | Exibe diferenças | `git diff --staged` |
| `git show <obj>` | `-s`, `--name-only` | Exibe commit/objeto | `git show HEAD` |
| `git blame <arquivo>` | `-L` | Mostra autoria por linha | `git blame -L 10,50 Calc.java` |
| `git grep <padrão>` | `-n`, `-i`, `-e`, `-C` | Busca texto no conteúdo rastreado | `git grep -ni "TODO"` |
| `git reflog` | — | Mostra movimentações locais de referências | `git reflog` |

### Diferença útil

```bash
git diff
```

→ alterações fora do staging.

```bash
git diff --staged
```

→ alterações que estão no staging.

# 🧳 Stash e limpeza

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git stash` | `-u`, `-a`, `-p` | Guarda alterações temporariamente | `git stash -u` |
| `git stash pop` | — | Aplica e remove o stash mais recente | `git stash pop` |
| `git stash apply` | — | Aplica sem remover da lista | `git stash apply` |
| `git stash list` | — | Lista stashes | `git stash list` |
| `git stash drop` | — | Remove um stash | `git stash drop` |
| `git clean` | `-n`, `-f`, `-d`, `-x` | Remove arquivos não rastreados | `git clean -n -d` |

> ⚠️ Execute `git clean -n` antes de `git clean -f` para visualizar o que seria removido.

# ⏪ Recuperação e reescrita

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git reset <ref>` | `--soft`, `--mixed`, `--hard` | Move HEAD e, dependendo da opção, índice/working tree | `git reset --soft HEAD~1` |
| `git revert <hash>` | `-n`, `--no-edit` | Cria novo commit que desfaz outro | `git revert <hash>` |
| `git bisect` | `start`, `bad`, `good` | Localiza commit que introduziu um problema | `git bisect start` |
| `git reflog` | — | Pode ajudar a recuperar referências locais | `git reflog` |

> ⚠️ `git reset --hard` pode descartar alterações locais.

# 🏷️ Tags, submódulos e worktrees

| Comando | Flags comuns | Para que serve | Exemplo |
|---|---|---|---|
| `git tag` | `-a`, `-d`, `-n` | Cria, lista ou remove tags | `git tag -a v1.0 -m "release"` |
| `git push origin <tag>` | `--tags` | Envia tags | `git push --tags` |
| `git submodule add` | `-b <branch>` | Adiciona outro repositório como submódulo | `git submodule add -b main <url> libs/lib` |
| `git submodule update` | `--init`, `--recursive` | Inicializa/atualiza submódulos | `git submodule update --init --recursive` |
| `git worktree add` | `-b` | Cria outra working tree ligada ao mesmo repositório | `git worktree add -b fix/x ../fix-x main` |

> 💡 Um submódulo registra um **commit específico** do repositório referenciado.  
> A opção `-b <branch>` configura a branch usada para acompanhamento em operações compatíveis; não significa que o submódulo deixe de apontar para um commit registrado.

# 🏷️ Flags curtas

> A mesma flag pode ter significados diferentes dependendo do comando.

| Flag | Comandos comuns | Significado prático |
|---|---|---|
| `-a` | `commit`, `branch`, `stash` | varia: arquivos rastreados / todas branches / stash incluindo ignorados |
| `-A` | `add` | adiciona todas as mudanças ao staging |
| `-b` | `checkout`, `clone`, `status`, `diff` | significado depende do comando |
| `-B` | `checkout` | cria/recria branch |
| `-c` | `switch` | cria uma nova branch |
| `-d` | `branch`, `tag` | remove |
| `-D` | `branch` | remove branch forçando |
| `-f` | `rm`, `clean`, `push` | força a operação |
| `-i` | `rebase`, `grep` | interativo / case-insensitive |
| `-l` | `config` | lista configurações |
| `-m` | `commit`, `branch`, `tag` | mensagem ou renomeação |
| `-n` | `log`, `clean`, `grep`, `revert` | varia conforme o comando |
| `-p` | `add`, `restore`, `stash` | modo patch/interativo |
| `-r` | `rm`, `branch` | recursivo / branches remotas |
| `-s` | `status`, `show` | formato curto / sem diff |
| `-S` | `commit` | assina commit |
| `-u` | `push`, `stash`, `branch` | upstream / inclui untracked |
| `-v` | `remote`, `commit` | modo detalhado |
| `-w` | `diff` | ignora whitespace |
| `-x` | `clean`, `cherry-pick` | varia conforme o comando |
| `-L` | `blame` | intervalo de linhas |

# 🧵 Flags longas

| Flag | Comando(s) | Para que serve |
|---|---|---|
| `--global` | `config` | configuração do usuário |
| `--list` | `config` | lista configurações |
| `--staged` | `diff`, `restore` | opera sobre staging |
| `--cached` | `rm` | remove apenas do índice |
| `--all` | `fetch`, `log` | todas as refs/remotos conforme contexto |
| `--tags` | `fetch`, `push` | inclui tags |
| `--rebase` | `pull` | integra usando rebase |
| `--ff-only` | `pull`, `merge` | permite apenas fast-forward |
| `--no-ff` | `merge` | força commit de merge |
| `--squash` | `merge` | combina mudanças sem criar merge commit |
| `--continue` | `rebase`, `cherry-pick` | continua após resolução |
| `--abort` | `merge`, `rebase`, `cherry-pick` | aborta a operação |
| `--onto` | `rebase` | redefine a base de commits |
| `--depth 1` | `clone` | clone raso |
| `--single-branch` | `clone` | limita clone a uma branch |
| `--name-only` | `diff`, `show`, `log` | exibe apenas nomes |
| `--no-edit` | `revert`, `merge` | usa mensagem padrão |
| `--force-with-lease` | `push` | force push com proteção adicional |

# ⚠️ Comandos que merecem cuidado

```bash
git reset --hard
git clean -f
git branch -D
git push --force
```

Antes de executar, confirme:

```bash
git status
git log --oneline --graph --decorate --all
```

Para reescrita remota, quando realmente necessária, prefira:

```bash
git push --force-with-lease
```

em vez de:

```bash
git push --force
```

# 🚀 Fluxo rápido de trabalho

```bash
git switch main
git pull

git switch -c feature/minha-tarefa

# editar arquivos

git status
git diff
git add .
git diff --staged
git commit -m "feat: implementa minha tarefa"

git push -u origin feature/minha-tarefa
```

Depois, abra o Pull Request.

# 🧠 Atalhos úteis

```bash
git status -sb
```

Status resumido + branch.

```bash
git branch --show-current
```

Branch atual.

```bash
git log --oneline --graph --decorate --all
```

Histórico visual.

```bash
git diff
```

Mudanças fora do staging.

```bash
git diff --staged
```

Mudanças no staging.

```bash
git fetch origin
```

Atualiza referências remotas.

```bash
git restore --staged <arquivo>
```

Remove arquivo do staging.

```bash
git restore <arquivo>
```

Descarta alterações locais do arquivo.

# 📚 Ajuda

Ajuda curta:

```bash
git <comando> -h
```

Documentação completa:

```bash
git <comando> --help
```

Exemplo:

```bash
git rebase --help
```

> 💡 Pratique os comandos potencialmente destrutivos em um repositório de testes antes de utilizá-los em projetos reais.
