# 🚀 Guia de Git — Comandos Básicos + GitHub/PR

Este guia apresenta um passo a passo para praticar os principais comandos do Git em um repositório local e também como conectar o projeto ao GitHub para usar `push`, `pull`, `clone` e Pull Requests.

> ✅ **Pré-requisitos**
>
> Para a parte local:
> - Git instalado;
> - terminal, Git Bash ou terminal da IDE.
>
> Para a parte **GitHub / Remoto / PR**:
> - conta no GitHub;
> - repositório criado no GitHub;
> - Git configurado;
> - para usar `gh pr create`, GitHub CLI (`gh`) instalado e autenticado.

---

## 1️⃣ Criar pasta e iniciar o repositório

```bash
mkdir git-teste
cd git-teste
git init -b main
```

O parâmetro `-b main` define explicitamente `main` como branch inicial.

Verifique:

```bash
git status
```

---

## 2️⃣ Configurar usuário

Caso ainda não tenha configurado o Git:

```bash
git config --global user.name "Seu Nome"
git config --global user.email "seu@email.com"
```

Para conferir:

```bash
git config --list
```

---

## 3️⃣ Criar arquivo e fazer o primeiro commit

```bash
echo "Hello Git!" > arquivo.txt
git status
git add arquivo.txt
git commit -m "chore: adiciona arquivo inicial"
```

### O que aconteceu?

1. `arquivo.txt` foi criado;
2. `git add` enviou a alteração para a área de **staging**;
3. `git commit` registrou a versão no histórico.

---

## 4️⃣ Ver o histórico de commits

```bash
git log --oneline
```

Para uma visualização mais completa:

```bash
git log --oneline --graph --decorate --all
```

---

## 5️⃣ Criar uma nova branch

```bash
git switch -c nova-feature
```

> `git switch -c` cria a branch e já muda para ela.

Confirme a branch atual:

```bash
git branch --show-current
```

ou:

```bash
git status -sb
```

---

## 6️⃣ Alterar um arquivo na nova branch

```bash
echo "Linha nova na branch nova-feature" >> arquivo.txt
git diff
```

Depois:

```bash
git add arquivo.txt
git diff --staged
git commit -m "feat: adiciona nova linha"
```

### Diferença importante

```bash
git diff
```

Mostra alterações **ainda não adicionadas ao staging**.

```bash
git diff --staged
```

Mostra alterações **que irão para o próximo commit**.

---

## 7️⃣ Voltar para a branch principal

```bash
git switch main
```

Veja o conteúdo do arquivo novamente:

```bash
cat arquivo.txt
```

A alteração feita em `nova-feature` ainda não está na `main`.

---

## 8️⃣ Mesclar a branch

Estando na `main`:

```bash
git merge nova-feature
```

Depois:

```bash
git log --oneline --graph --decorate --all
```

---

## 9️⃣ Excluir uma branch local já integrada

Depois do merge:

```bash
git branch -d nova-feature
```

> ⚠️ `-d` exclui com segurança uma branch já integrada.  
> `-D` força a exclusão e deve ser usado com cuidado.

---

## 🔎 10) Ver diferenças e status

Edite novamente o arquivo:

```bash
echo "Outra alteração" >> arquivo.txt
```

Veja o status:

```bash
git status
```

Veja as alterações:

```bash
git diff
```

Se quiser descartar a alteração local:

```bash
git restore arquivo.txt
```

> ⚠️ `git restore` descarta alterações não commitadas do arquivo.

---

## 🗑️ 11) Remover um arquivo

Uma forma recomendada:

```bash
git rm arquivo.txt
git status
git commit -m "chore: remove arquivo.txt"
```

`git rm` remove o arquivo e já registra a remoção na área de staging.

# 🌐 Parte Remota — GitHub

## 📥 12) Clonar um repositório existente

```bash
git clone https://github.com/SEU_USUARIO/git-teste.git
```

Clonar em uma pasta com outro nome:

```bash
git clone https://github.com/SEU_USUARIO/git-teste.git meu-projeto
```

Clonar uma branch específica:

```bash
git clone -b develop --single-branch https://github.com/SEU_USUARIO/git-teste.git
```

---

## 🔗 13) Conectar um repositório local ao GitHub

No GitHub, crie um **repositório vazio**, sem README, `.gitignore` ou licença.

Depois:

```bash
git remote add origin https://github.com/SEU_USUARIO/git-teste.git
```

Confirme:

```bash
git remote -v
```

Como o repositório já foi criado com:

```bash
git init -b main
```

não é necessário renomear a branch.

> Caso esteja trabalhando em um repositório antigo cuja branch principal seja `master`, pode renomeá-la com:
>
> ```bash
> git branch -M main
> ```

---

## ⬆️ 14) Enviar commits para o GitHub

No primeiro envio:

```bash
git push -u origin main
```

O `-u` define `origin/main` como upstream da branch local.

Nos próximos envios:

```bash
git push
```

---

## ⬇️ 15) Trazer alterações do GitHub

```bash
git pull origin main
```

De forma simplificada:

```text
git pull = git fetch + integração das alterações
```

A forma de integração pode variar conforme a configuração do Git, por exemplo merge ou rebase.

Para somente consultar/baixar atualizações sem modificar imediatamente a branch local:

```bash
git fetch origin
```

# 🔀 16) Fluxo de Pull Request

## a) Atualizar a `main`

```bash
git switch main
git pull origin main
```

## b) Criar uma branch para a tarefa

```bash
git switch -c feature/melhoria-doc
```

Faça a alteração:

```bash
echo "Nova seção de documentação" >> README.md
```

Depois:

```bash
git add README.md
git commit -m "docs: adiciona nova seção no README"
```

## c) Enviar a branch

```bash
git push -u origin feature/melhoria-doc
```

## d) Abrir o Pull Request

### Pelo site

No GitHub, normalmente aparece a opção:

**Compare & Pull Request**

Confira:

- branch base: `main`;
- branch de comparação: `feature/melhoria-doc`;
- título;
- descrição;
- reviewers, quando aplicável.

### Pela GitHub CLI

Se `gh` estiver instalado e autenticado:

```bash
gh pr create \
  --base main \
  --head feature/melhoria-doc \
  --title "docs: nova seção" \
  --body "Adiciona uma nova seção de documentação ao README."
```

## e) Depois do merge

Atualize a branch local:

```bash
git switch main
git pull origin main
```

Exclua a branch local, se ela não for mais necessária:

```bash
git branch -d feature/melhoria-doc
```

Opcionalmente, exclua também a branch remota:

```bash
git push origin --delete feature/melhoria-doc
```

# 💻 Usando GitHub Codespaces

O GitHub Codespaces permite praticar Git diretamente no navegador usando uma interface semelhante ao VS Code.

## Como abrir

1. Acesse o repositório no GitHub.
2. Clique em **Code**.
3. Abra a aba **Codespaces**.
4. Clique em **Create codespace on main**.

No terminal integrado, teste:

```bash
git status
git branch --show-current
git log --oneline
```

## Vantagens

- Git já disponível no ambiente;
- terminal integrado;
- editor visual;
- facilidade para testar branches, commits e conflitos;
- integração direta com o GitHub.

> 💡 Em um Codespace criado a partir de um repositório existente, não é necessário executar `git init`, pois o projeto já é um repositório Git.

## 🧠 Comandos essenciais

```bash
git status
git add .
git commit -m "mensagem"
git log --oneline
git switch -c nome-da-branch
git switch main
git merge nome-da-branch
git fetch origin
git pull
git push
```

> 💡 O comando `git checkout` continua existindo e aparece em muitos projetos antigos. Para novos exemplos didáticos, `git switch` e `git restore` tornam a intenção do comando mais clara.
